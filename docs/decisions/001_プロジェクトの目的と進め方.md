# 001 プロジェクトの目的と進め方

- 状態: 採用
- 日付: 2026-10-14
- 関連: spec/01_概要.md

## 背景

初回のビルドが通ったあと、既存のバグ4件をどう扱うか（直すか、試作として放置するか）を確認する必要があった。

## 決定

- 主目的は、Mac・Xcodeを使わず、WindowsとGitHub ActionsだけでiPhoneアプリを作り、実機へ入れられるかを検証すること。
- 副目的は、晴樹さん本人が日常の作業で実際に使えるアプリにすること。そのためバグは直す。
- 目的が分かる範囲の判断はAIが行い、確認を求めずに進める。確認するのは、外部への公開、課金、取り消せない操作だけ。

## 理由

晴樹さんの発言（2026-10-14）:

> B　これの目的はiphoneアプリをwindowsだけでつくれるかみることです。でも使ってみたいアプリではあるからバグはなおしてほしい　そういうもくてきなのがわかればできるだけ判断を仰がずにすすめて

> 些細な事項の判断はあなたにまかせます。とりあえずうごかしたい

## 実装の担当

- 当初は「claudeトークン節約のためにできるだけ実装などはcodexにおねがい」という方針で、バグ修正（ADR-017）はCodexが実装した。
- A/Bの実装からは「codexにまかせなくてよい」とされ、Claudeが直接実装した。

## リポジトリ

- リポジトリ名はフォルダ名と同じ `FocusTimer` にした。最初は非公開。
- のちに「リポジトリを公開にする　をやってくれ」で公開した。公開前に、過去のコミットも含めて秘密情報がないことを確認した。
- 公開によって見えるようになったもの: コミットのメールアドレス、「晴樹さん」という名前、カンガルーのファイル名。
- 公開リポジトリではActionsのmacOSランナーが無料になる。ReleaseのIPAも認証なしでダウンロードできる（ADR-015）。

## TDDの扱い

- 原則はテスト先行。テストを先に別のコミットにした（例: `0bb1c61` → `0d543fb`）。
- Swiftでは、実装前にテストを動かしてもコンパイルエラーで止まるだけなので、「赤を確認する」手順は省いた。

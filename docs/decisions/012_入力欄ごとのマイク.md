# 012 入力欄ごとのマイクと、音声入力ブロックの扱い

- 状態: 採用
- 日付: 2026-10-14
- 関連コミット: `98b36cf`
- 関連: spec/02_機能仕様.md（F6）

## 背景

晴樹さんの質問:

> 音声入力のボタン での音声入力っていうのはオリジナルの実装なんですか？それとも iphoneの音声入力機能ですか…テキスト入力欄の近くにその音声入力は始めるっていうボタンをつけるのではだめだったんでしょうか

音声入力はSpeechフレームワークによる独自実装だった。独立したブロックにしていたのは、要件書の「話した文章からゴール・工程・時間を自動で取り出す」構想の入口として作ったため。ただし、自動で取り出す機能はまだ作っていなかった。

## 検討した選択肢

1. 各入力欄にマイクボタンを付ける（おすすめとして提示）
2. キーボードの音声入力だけを使う。独自実装をやめる（入力の手間が増える）

## 決定

晴樹さんの発言:

> １だけど別ブロックも一番下に移動してのこしておいて

- 各入力欄（作業名、今日のゴール、工程、完成条件、あとでやること）の横にマイクを置く。押した欄に直接入力される。
- 従来のブロックは画面の最下部に残す。将来の自動抽出の入口にするため。

## 実装上の判断

- 別の欄のマイクに切り替えたとき、前の欄に入力されない不具合が見つかった。録音の終了を画面状態の変化から判断していたのをやめ、`SpeechInput.onFinish` のコールバックで受け取るようにした。
- 完成条件とあとでやることは、録音が止まった時点で保存する。完成条件は通知とLive Activityにも反映する。

## 残るリスク

実機での動作は、まだ確認していない。最初に直した不具合（録音を止めたときにエラーが出る）も同様。

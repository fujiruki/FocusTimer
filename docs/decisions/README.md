# 設計判断記録（ADR）

仕様書（`docs/spec/`）には「何を作るか」を書きます。ここには「なぜそう決めたか」を残します。判断が必要になった背景、検討した選択肢、決めた理由、根拠、残るリスクを書きます。

- 形式: ADR（Architecture Decision Record）。1判断1ファイルで、番号は通しにします。
- 判断を覆す場合は、元のファイルを消さず、新しいADRを追加して元の状態を「置き換え済み（ADR-NNN）」にします。
- 晴樹さんの発言は、できるだけ原文のまま引用します。
- 出典の略称:
  - 要件書: カンガルー `2026-10-13_02_タイマーアプリ_iPhone_AppleWatch_音声入力_要件・仕様案_引き継ぎ.md`
  - 提案書: カンガルー `2026-10-14_02_ChatGPT宛_…提案.md`（Claudeが作成）
  - 決定記録: カンガルー `2026-10-14_03_ClaudeCode宛_フォーカスタイマー_LiveActivity_途中通知_初期実用版_決定記録.md`

## 書式

```
# NNN タイトル
- 状態: 提案中 / 採用 / 置き換え済み（ADR-NNN） / 廃止
- 日付・関連コミット・関連仕様
## 背景
## 検討した選択肢
## 決定
## 理由
## 根拠・調査
## 影響・残るリスク
```

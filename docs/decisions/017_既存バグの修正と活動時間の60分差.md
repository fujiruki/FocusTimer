# 017 既存バグ4件の修正と、活動時間の最小差を60分にそろえる

- 状態: 採用
- 日付: 2026-10-14
- 関連コミット: `119fc9b`（Codex）、`bb78aa6`、`4d77674`

## 背景

最初にコードを読んだときに、バグの候補を4件見つけた。ADR-001 の方針（使うのでバグは直す）に従って直した。

## 決定（修正内容）

1. 「工程も完了」が切り替え式だったため、完了済みの工程が未完了に戻ることがあった → 完了にするだけの `setStepDone` にした。
2. 録音を止めたとき、`task.cancel()` によるエラーが赤字で出ていた → 止めたあとに届く古い結果は無視するようにした。
3. 活動の開始が終了より遅くなる設定を防いでいなかった → 開始と終了を60分以上離すようにした。
4. 日付が変わっても前日の作業が残っていた → 作業と予約済みの通知も破棄するようにした。

## 60分差にそろえた理由

Codex のレビュー（P2）で、画面のボタンは60分以上の差を求めているのに、保存値の補正は1分差しか確保していないと指摘された。たとえば 18:00〜18:00 が 18:00〜18:01 に補正され、画面からは選べない値が残っていた。そこで、補正も画面と同じ60分差にそろえた。

## 追加の修正

テストで、初期化の途中で `didSet` の補正が働き、18:00〜18:00 が 17:00〜18:00 になることが分かった。そこで、読み込み中は補正を止め（`normalizingMinutes`）、読み込みが終わってから一度だけ正規化するようにした。

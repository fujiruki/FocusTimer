# 006 途中通知の間隔・件数・文面と「強めない」方針

- 状態: 採用
- 日付: 2026-10-14
- 関連: spec/02_機能仕様.md（F9）、`ReminderPlanner`

## 決定と理由

| 決定 | 理由・根拠 |
|:--|:--|
| 間隔はオフ／5／10／15分、初期値は10分 | 要件書では、5分ごとや5・15・25・30分などは会話中の例で、確定していなかった。提案書で「仮の初期値は10分（試用して決める）」とし、決定記録4で「原則10分間隔の初期値」と決まった |
| 「残り半分」の通知は廃止し、N分ごとの途中通知に置き換える。残り5分と終了の通知は残す | 決定記録で「既存の残り半分通知は置換可」とされた。半分の1回だけでは、5〜10分で忘れる問題に間に合わない |
| 途中通知は最大40件 | iOSで予約できるローカル通知は64件まで。のちに鳴らし直しの20件を加え、合計は最大62件（ADR-013） |
| 残り5分・終了の前後60秒以内なら途中通知を出さない | 提案書で「1分以内に重なる通知はまとめる」とした。ほぼ同時に2回鳴るとうるさい |
| 通知に応答ボタンを付けない | 要件書に「通知への返答は必須にしない。閉じたことを順調と記録しない」とある。AIの最初の案にあった「続ける／脱線した」ボタンは、この方針に反するため外した。+5分や後回しメモのボタンも、決定記録5で「必須としない。まず表示・気づき・元作業への復帰を実機評価」となった |
| 反応がなくても通知を強めない | 要件書に「無反応だけで通知を強くし続けない」とある。例外は、晴樹さんが明示的に選ぶ「気づくまで鳴らす」（ADR-013）だけ |
| タイトルは完成条件、本文は「残り◯分／今日のゴール：◯◯」 | 通知を見た瞬間に、何をどこまでやるのかを思い出せるようにするため。赤や警告調の言い回しは避ける（提案書） |

## 影響・残るリスク

- コードには旧識別子 `focus-half` の取り消し処理が残っている。旧版で予約した通知を消すためと考えられる。
- 10分という初期値が適切かは、実際に使って決める。

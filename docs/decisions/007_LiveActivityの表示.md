# 007 Live Activityの表示優先順位とレイアウト

- 状態: 採用
- 日付: 2026-10-14
- 関連コミット: `0c78618`, `e0c9eae`, `a0c783a`
- 関連: spec/02_機能仕様.md（F10）、spec/03_画面設計.md

## 背景

- 決定記録2の時点での優先順位は「完成条件 → 残り時間 → 今日のゴール」だった。
- 実機では工程名だけが出て、ゴール名が見えなかった。晴樹さんの発言:

> ロック画面で、工程名はでてるけど、同時にゴール名もでてほしいな

## 決定

1. 表示の優先順位は「1. 今回の完成条件、2. 今日のゴール、3. 残り時間と進捗バー」とする。
2. ゴール名は専用の行に必ず出す。工程名はその後ろに小さく添え、長いときに省略されるのは工程名のほうにする。
3. 完成条件が未入力のときは、小見出しを「今の作業」にして作業名を出す。
4. ゴールに紐づかない作業では「今日のゴール 未設定」と薄く出す。
5. 残り時間は1行目の右に置き、ゴールは小見出しと同じ行に置いて、高さを抑える。
6. 時間切れ後は0で止める。超過時間を常に更新し続けることは後で検討する（決定記録6）。
7. 初期版ではボタンを付けない（決定記録5）。

## 理由

晴樹さんの指示（貼り付け）:

> 理由：完成条件だけでなく、今日のゴールも見えることで、『何のために今これをやっているか』を思い出しやすくなり、集中しやすくなるため

> 文字数が長い場合は省略してよいですが、意味が分からなくなるほど削らないでください

- 4「未設定」: 紐づけ忘れを、表示を見ただけで気づけるようにするため（ADR-009）。
- 5 高さ: ロック画面の Live Activity は高さ約160ptが上限で、超えた部分は切れる。修正前の配置は計算上この上限をわずかに超えていて、ゴールの行が削られた可能性があった。

## 影響・残るリスク

- ゴールが見えなかった本当の原因は、高さではなく、作業がゴールに紐づいていなかったことだった（ADR-009）。高さを詰めた変更はそのまま残している。
- 修正後のロック画面は、実機でまだ確認していない。
